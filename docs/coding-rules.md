# コーディングルール

基本的には [Google C++ Style Guide](https://google.github.io/styleguide/cppguide.html) に従います。
この文書では、 Google C++ Style Guide よりも優先される Lumino 固有のガイドラインについて説明します。

## API として公開する型定義

- [MUST] packages\LuminoC\include\LuminoC\lumino_types.h で定義し、 C++ 側でも参照して使います。
  - これは依存レイヤーの逆転で、本来は C++ 側の `enum class` と C_API 側の `enum` を別々に定義するのが綺麗でしょう。しかし定義やドキュメンテーションコメントの多重管理などの保守コストが大きく、小規模メンバーでメンテナンスする Lumino では、定義を一箇所にまとめることにしました。

## 命名

- [MUST] クラスのメンバ変数には `m_` を前置します。(例: `m_size`, `m_refCount`)
  - Google C++ Style Guide はメンバ変数を後置 `_` (`size_`) と規定していますが、 Lumino では前置 `m_` を採用します。既存コードの大半が `m_` であることに加え、エディタの補完で `m_` と入力するとメンバだけを絞り込めるためです。
  - struct の public なデータメンバ (`Vector3::x` など、単なる値の集合) には前置しません。

## パッケージの命名

`packages/` 以下のパッケージ名は、成果物の種類に応じて規則が異なります。

- [MUST] C++ ライブラリは PascalCase で書き、`Lumino` を前置します。(例: `LuminoBase`, `LuminoCore`, `LuminoShader`, `LuminoC`)
  - CMake のターゲット名はグローバルな名前空間に置かれます。他プロジェクトに取り込まれたときの衝突を避けるため、接頭辞は省略しません。
- [MUST] 実行ファイル (ツール) と npm パッケージは lowercase で書きます。(例: `luminosc`, `luminojs`)
  - lowercase にするのは、広く行き渡っている慣例に合わせるためです。npm はパッケージ名に大文字を使えません。

## フォーマット

- [MUST] if や for などの制御文は必ずブロック `{}` で囲むこと。
  - 例外: 関数先頭の早期 return に限り、ブロックを省略することができます。
- [MUST] ドキュメンテーションコメントは `/** */` スタイルで書きます。
- [MUST] 区切り線を使う場合は `//------------------------------------------------------------------------------` のようにし、列数 80 文字で統一します。
- [MUST] 改行コードは LF を使用します。
- [MUST] 文字コードは UTF-8 (BOM 付き) を使用します。BOM が外れていると C4819 警告が /WX によりエラー扱いされてビルドが失敗します。PowerShell や Write 系ツールでファイルを新規作成すると BOM が付かないことがあるため注意してください。
